# 문제 제작기 (Problem Maker)

Color Guesser 게임과 같은 프로젝트 안에서 실행되는 로컬 문제 제작 도구입니다.
실제 사진을 불러와 색을 바꿀 영역(마스크)을 그리고, 정답 색상을 자동으로
추출한 뒤, 게임이 바로 인식할 수 있는 문제 파일(`question.json` +
`original.webp` + `mask.png` + `thumbnail.webp`)로 내보낼 수 있습니다.

모든 작업은 브라우저 안에서만 이루어지며, 이미지나 작업물을 외부 서버로
전송하지 않습니다.

## 실행 방법

이 프로젝트는 빌드 과정이 없는 정적 사이트라서, 게임 본체와 같은 로컬
서버로 함께 뜹니다.

```powershell
cd C:\colorguesser
npm install
npm run dev
```

서버가 뜨면 아래 주소로 접속하세요.

```text
문제 제작기: http://localhost:5173/problem-maker/
게임 본체:   http://localhost:5173/
```

## 이미지 불러오기

시작 화면에서 다음 중 하나로 이미지를 불러옵니다.

- `새 문제 만들기` 또는 `이미지 불러오기` 버튼 → 파일 선택 창
- 화면의 점선 영역에 이미지 파일을 드래그 앤 드롭

지원 형식은 PNG, JPG/JPEG, WebP이며, 이미지 방향(EXIF)은 자동으로 정상
방향으로 보정됩니다.

이미지를 불러오면 출력 해상도를 고를 수 있는 창이 뜹니다.

- **긴 변 기준 2048px로 맞추기** (기본값, 원본이 더 작으면 그대로 둡니다)
- **원본 해상도 그대로 사용** (단, 브라우저가 멈추지 않도록 긴 변을
  4096px로 제한합니다)

여기서 고른 해상도가 이후 마스크 편집과 최종 출력 파일의 해상도가 됩니다
(원본과 마스크는 항상 정확히 같은 크기로 만들어집니다).

## 화면 구성

- **상단**: 로고, 파일명, 저장 상태, 실행 취소/다시 실행, 새 작업, 기존
  문제 열기, 단축키 도움말
- **왼쪽**: 선택 도구(브러시/지우개/다각형/스마트 선택/스포이드)
- **중앙**: 이미지 편집 캔버스 + 확대/축소/뷰 모드 툴바
- **오른쪽**: 문제 정보 / 마스크 / 정답 색상 / 미리보기 / 썸네일 /
  내보내기 탭
- **하단**: 이미지 크기, 확대율, 마스크 픽셀 수/비율, 현재 좌표

화면에 보이는 확대·축소는 화면 표시만 바꾸는 것이고(CSS로만 확대),
편집 캔버스 자체의 실제 픽셀 크기는 항상 고정되어 있습니다. 그래서
어떤 배율로 보고 있어도 브러시가 찍는 좌표는 항상 실제 이미지 픽셀과
정확히 일치합니다.

## 마스크 도구 사용법

오른쪽 패널의 "마스크" 탭에서 브러시 크기/경도, 스마트 선택 허용
오차/범위, 확정 시 추가·제거 여부, 오버레이 색상/투명도를 조절할 수
있고, 아래 버튼들로 마스크 전체에 후처리를 적용할 수 있습니다.

| 버튼 | 동작 |
|---|---|
| 전체 선택 | 마스크 전체를 선택 상태로 채움 |
| 전체 해제 | 마스크를 완전히 비움 |
| 마스크 반전 | 선택/비선택을 뒤집음 |
| 선택 영역 확장 | 지정한 픽셀만큼 선택 영역을 넓힘 |
| 선택 영역 축소 | 지정한 픽셀만큼 선택 영역을 좁힘 |
| 가장자리 부드럽게 | 알파 경계를 흐려서 자연스럽게 만듦 |
| 작은 구멍 채우기 | 확장 후 축소(모폴로지 닫힘)로 내부의 작은 구멍을 메움 |
| 고립 픽셀 제거 | 지정한 픽셀 수보다 작은 조각을 찾아서 지움 |

캔버스 위 툴바의 "기본 / 마스크만 / 원본만 / 색상 결과" 버튼으로 보기
모드를 바꿀 수 있습니다. "마스크만"은 실제로 저장될 마스크(흰색+알파)를
검은 배경 위에 그대로 보여주고, "색상 결과"는 게임과 완전히 같은 방식
(`preserve-lightness`)으로 색을 바꾼 결과를 보여줍니다.

## 브러시와 지우개

- 브러시(단축키 `B`): 드래그한 자리를 마스크에 추가합니다.
- 지우개(단축키 `E`): 드래그한 자리를 마스크에서 지웁니다.
- 둘 다 크기와 경도(가장자리 부드러움)를 "마스크" 탭에서 조절합니다.
- 드래그 중에는 마우스 이동 거리에 따라 점을 촘촘히 찍어서 선이 끊기지
  않게 합니다.
- 다각형 선택(단축키 `P`): 점을 여러 번 클릭해 다각형을 만들고, 첫 점
  근처를 다시 클릭하거나 `Enter`를 누르면 닫힙니다. `Esc`로 취소합니다.

## 스마트 선택 허용 오차

스마트 선택(단축키 `W`, 포토샵의 마술봉과 비슷한 기능)은 클릭한 픽셀의
색을 기준으로 유사한 색을 가진 영역을 골라줍니다. 실제 AI 모델을 쓰지
않으므로 "AI 선택"이라고 부르지 않습니다.

- **허용 오차**: 클릭한 픽셀과 다른 픽셀 사이의 LAB 색공간 거리
  (deltaE) 기준값입니다. 값이 클수록 더 넓은 색 범위까지 선택됩니다.
  단순 RGB 차이 대신 LAB 거리를 쓰는 이유는, 사람이 실제로 느끼는 색
  차이와 더 비슷하고 밝기 변화에 덜 민감하기 때문입니다.
- **인접 픽셀만 / 이미지 전체에서**: 클릭한 지점과 이어져 있는 영역만
  고를지, 이미지 전체에서 비슷한 색을 다 고를지 선택합니다.
- 선택 결과는 바로 반영되지 않고 주황색으로 미리보기만 됩니다.
  `Enter`로 확정(마스크에 추가/제거는 "마스크" 탭의 설정을 따름)하거나
  `Esc`로 취소합니다.

## 정답 색상 자동 추출 방식

"정답 색상" 탭의 `마스크에서 정답 색상 추출` 버튼을 누르면 다음 순서로
계산합니다 (`problem-maker/js/color-extractor.js`).

1. 마스크 알파값이 일정 기준 이상인 픽셀만 모읍니다.
2. 알파값을 그대로 가중치로 씁니다(알파가 낮은 가장자리는 영향을 덜 줌).
3. 픽셀이 너무 많으면(기본 6,000개 초과) 결정적으로(순서 기반, 난수
   없이) 균일하게 골라 상한을 둡니다.
4. sRGB를 LAB로 바꾸고, 밝기 상하위 5%(하이라이트/그림자로 의심되는
   값)는 가중치를 절반으로 낮춥니다(완전히 버리지는 않습니다).
5. LAB 공간에서 가중 평균, 가중 중앙값, 가중 k-평균 군집화(기본
   3군집)를 모두 계산합니다. 군집 초기값은 "이미 고른 중심들로부터
   가장 먼 점"을 반복해서 고르는 방식이라 완전히 결정적입니다(같은
   이미지+마스크면 항상 같은 결과).
6. 가장 비중이 큰 군집을 기본 추천으로 쓰되, 그 군집이 아주 어둡다면
   (그림자로 의심) 비중이 충분하고 더 밝은 다른 군집이 있으면 그쪽을
   대신 추천합니다.
7. 전체 가중치의 5% 미만인 군집은 후보에서 제외합니다.

결과로 "자동 추천", "가중 평균", "중앙값 계열", "주요 색상 1~4"
후보가 칩으로 표시되며, 클릭해서 바로 선택할 수 있습니다. "색상 분포
일관성" 막대는 가장 큰 군집이 전체에서 차지하는 비중을 보여주는
참고값일 뿐 정확도를 보장하지 않습니다.

## 자동 추출 결과 수정 방법

같은 탭에서 다음 방법으로 직접 보정할 수 있습니다.

- **HEX 직접 입력**
- **RGB / HSL 슬라이더**
- **스포이드**(단축키 `I`): 원본 이미지의 실제 픽셀 색을 읽습니다(화면에
  보이는 마스크 오버레이 색이 아닙니다). 1×1/5×5/7×7 평균 범위를 고를
  수 있습니다.
- **자동 추천색으로 되돌리기** 버튼
- **최근 선택 색상** 목록에서 다시 클릭

## 썸네일 생성 방법

"썸네일" 탭에서 원본 사진을 기준으로 정사각형(기본 512×512, WebP 품질
0.88)으로 잘라냅니다. 드래그로 중심 위치를 옮기고, 휠이나 슬라이더로
확대할 수 있습니다. 게임의 카테고리 카드나 문제 목록은 원래도 정답
색상이 그대로 담긴 사진을 보여주는 구조라서(원본 사진 자체가 이미
정답색입니다), 별도의 "정답색 적용판"을 새로 합성하지 않고 원본 사진을
그대로 기준으로 삼습니다.

## ZIP 내보내기

"내보내기" 탭에서 순서대로 진행합니다.

1. `검증 결과 보기`로 문제가 없는지 확인합니다(오류가 있으면 내보내기
   가 자동으로 막힙니다).
2. `ZIP으로 내보내기`를 누르면 4개 파일(question.json, original.webp,
   mask.png, thumbnail.webp)을 모두 메모리에서 먼저 만든 뒤, 전부
   성공했을 때만 다음 구조의 ZIP을 다운로드합니다.

```text
문제ID.zip
└─ 문제ID/
   ├─ question.json
   ├─ original.webp
   ├─ mask.png
   └─ thumbnail.webp
```

## 게임 프로젝트에 바로 추가하기

Chrome/Edge처럼 File System Access API를 지원하는 브라우저에서는
`게임 프로젝트에 바로 추가` 버튼으로 ZIP 다운로드 없이 바로 등록할 수
있습니다.

1. 버튼을 누르면 폴더 선택 창이 뜹니다. **`C:\colorguesser` 폴더 자체를
   선택**하세요.
2. 선택한 폴더가 실제 Color Guesser 프로젝트인지 확인합니다
   (`package.json`, `src/data/categories.json`, `assets` 폴더 존재
   여부).
3. 어떤 경로에 어떤 파일이 만들어질지 미리 보여주고 최종 확인을
   받습니다.
4. 확인하면 카테고리 문제 JSON 파일을 **타임스탬프가 붙은 이름으로
   먼저 백업**한 뒤(`*.bak-YYYYMMDD-HHMMSS.json`), 이미지 3개를 쓰고,
   문제 JSON에 새 항목을 추가합니다.
5. 다 쓴 뒤 다시 읽어서 실제로 반영됐는지 확인하고 성공 메시지를
   보여줍니다.

이미 같은 이름의 폴더가 있거나 같은 id가 이미 등록되어 있으면 아무것도
바꾸지 않고 오류로 안내합니다. 브라우저가 이 기능을 지원하지 않거나
사용자가 폴더 선택을 거부하면 앱이 멈추지 않고 ZIP 방식과 아래
명령으로 안내합니다.

## import-question 명령 사용법

ZIP으로 받았다면, 압축을 풀어서 **ZIP 안의 폴더(문제ID 이름의 폴더)**
경로를 아래 명령에 넣어주세요.

```powershell
cd C:\colorguesser
npm run import-question -- "C:\다운로드경로\문제ID"
```

이 명령(`scripts/import-question.js`, 이번 작업 이전부터 있던 스크립트)
은 `question.json`을 검증하고, 카테고리 존재 여부와 id 중복을 확인한
뒤, 이미지를 `assets/questions/<categoryId>/<id>/`로 복사하고 해당
카테고리 JSON 파일에 문제를 추가합니다. 중간에 실패하면 복사한 파일까지
되돌리고 아무 것도 바꾸지 않습니다.

## 기존 문제 수정하기

시작 화면이나 상단 바의 `기존 문제 열기`로, 문제 제작기가 내보낸 ZIP을
다시 불러올 수 있습니다. 불러오면 원본 id를 그대로 유지(기존 문제 수정)
할지, 새 id로 복제할지 선택하는 창이 뜹니다. 이후 마스크 수정, 정답
색상 재추출/수동 변경, 제목·태그·난이도 수정, 썸네일 재설정을 모두 할
수 있고, 다시 ZIP으로 내보내거나 프로젝트에 바로 추가할 수 있습니다.

## 자동 저장과 복구

이미지 데이터는 용량이 커서 `localStorage`가 아니라 IndexedDB에
저장합니다.

- 편집 중 20초 간격 + 주요 작업(마스크 변경, 색상 확정 등) 후 자동 저장
- `Ctrl+S`로 즉시 임시 저장
- 시작 화면의 "최근 임시 작업" 목록에서 다시 불러오기/삭제 가능
- 브라우저를 닫았다 다시 열어도 목록에 남아있어 복구할 수 있음
- 저장하지 않은 변경사항이 있는 상태에서 새 작업을 시작하거나 창을
  닫으려 하면 확인을 한 번 더 받음
- IndexedDB를 지원하지 않는 브라우저에서는 자동 저장 없이 계속 작업할
  수 있다고 안내만 합니다(기능을 막지는 않음)

| 키 | 동작 |
|---|---|
| `B` | 브러시 |

| `Ctrl+Z` | 실행 취소 |
| `Ctrl+Y` / `Ctrl+Shift+Z` | 다시 실행 |
| `Ctrl+S` | 임시 저장 |
| `0` | 이미지에 맞춤 |
| `1` | 100% 보기 |

## 이미지 및 마스크 규격

| 항목 | 규격 |
|---|---|
| 원본 이미지 출력 | WebP (`original.webp`) |
| 마스크 이미지 | PNG, 알파 채널 필수 (`mask.png`), **원본과 정확히 같은 해상도** |
| 마스크 색 변경 영역 | 흰색(RGB 255,255,255) + 알파값 = 선택 강도 |
| 마스크 비변경 영역 | 완전 투명(alpha 0) |
| 마스크 가장자리 | 안티앨리어싱된 반투명 픽셀 허용 |
| 썸네일 | WebP, 기본 512×512, 품질 0.88 |

게임은 마스크의 **(밝기채널/255) × (알파/255)**를 색상 변경 강도로
사용합니다(흰색+불투명만 100% 강도). 색상 합성은 원본의 명도(L)는 그대로
두고 Hue/Saturation만 사용자가 고른 색으로 바꾸는 `preserve-lightness`
방식이라서 하이라이트/그림자/질감이 그대로 유지됩니다. 이 계산은 게임
본체의 `src/js/color/mask-renderer.js`를 문제 제작기가 그대로 가져다
쓰기 때문에, 제작기 미리보기와 실제 게임 화면이 항상 같습니다.

## 자주 발생하는 오류

| 상황 | 원인/해결 |
|---|---|
| "PNG, JPG, WebP 형식만 지원합니다" | 다른 형식(GIF, BMP, SVG 등)의 파일을 선택함 |
| "마스크가 비어 있습니다" | 색을 바꿀 영역을 하나도 선택하지 않고 내보내려 함 |
| "이미지 전체에 가깝게 선택되어 있습니다" (경고) | 실수로 전체 선택을 누른 채 그대로인 경우가 많음. 의도한 것이면 그대로 진행 가능 |
| "이미 사용 중인 id입니다" | 같은 카테고리 안에 같은 id의 문제가 이미 있음. 자동 생성 버튼으로 새 id를 받으세요 |
| "폴더에 직접 쓰는 기능을 지원하지 않습니다" | Chrome/Edge가 아니거나 오래된 버전. ZIP + `import-question` 명령을 쓰세요 |
| "선택한 폴더가 Color Guesser 프로젝트 구조와 다릅니다" | `C:\colorguesser` 폴더 자체가 아니라 다른 폴더를 선택함 |
| 자동 저장이 안 됨 | 브라우저가 IndexedDB를 차단(시크릿 모드 등)했을 수 있음 |

## Chrome/Edge를 권장하는 이유

- File System Access API(게임 프로젝트에 바로 추가)는 Chromium 계열
  브라우저에서만 지원됩니다.
- WebP 인코딩(`canvas.toBlob('image/webp', ...)`)이 안정적으로
  지원됩니다.
- `OffscreenCanvas`, `createImageBitmap`의 `imageOrientation` 옵션 등
  성능/호환 관련 기능도 Chromium 계열에서 가장 안정적으로 동작합니다.

다른 브라우저에서도 마스크 편집과 ZIP 내보내기 자체는 대부분 동작하지만,
"바로 추가" 기능만 자동으로 비활성화되고 ZIP + 명령줄 방식으로
안내됩니다.

## 브라우저가 로컬 폴더에 마음대로 쓸 수 없는 이유

웹 페이지는 보안상 사용자가 명시적으로 허용한 폴더/파일이 아니면 로컬
디스크에 접근할 수 없습니다. 그래서 이 도구는 사용자가
`showDirectoryPicker()`로 **직접 폴더를 선택했을 때만** 그 폴더 안에
씁니다. 이 확인 절차 없이 항상 `C:\colorguesser`에 자동으로 쓰려고
시도하는 기능은 만들 수도 없고, 만들지도 않았습니다.

## 게임과 공유하는 데이터 구조

다음 두 파일이 게임 본체와 문제 제작기가 공유하는 "계약"입니다. 필드
이름이나 의미를 문제 제작기 쪽에서 임의로 바꾸지 않습니다.

- `problem-maker/shared/question-schema.json` — 문제 1개의 JSON
  Schema. 내보내기 전 검증에서 이 파일을 실제로 fetch해서 검사합니다
  (하드코딩된 사본이 아닙니다).
- `problem-maker/shared/export-example.json` — 예시 `question.json`.

또한 다음 게임 본체 코드를 그대로 가져다 씁니다(복사해서 따로
관리하지 않음).

- `src/js/color/color-convert.js` — HEX/RGB/HSL/LAB 변환
- `src/js/color/delta-e.js` — LAB 색상 거리(deltaE76), 스마트 선택의
  허용 오차 계산에 사용
- `src/js/color/mask-renderer.js` — 색상 합성(미리보기), `MaskRenderer`
  클래스를 그대로 재사용
- `src/js/utils/validation.js` — `validateQuestionShape`,
  `findDuplicateIds`, `SUPPORTED_RENDER_MODES`

## 추후 실제 AI 세그멘테이션을 추가할 위치

지금의 "스마트 선택"은 LAB 색상 거리 기반의 색상 유사도 선택(포토샵
마술봉과 비슷한 방식)이며, 실제 AI 이미지 세그멘테이션 모델을 쓰지
않습니다. 나중에 실제 AI 기반 자동 영역 분할을 추가한다면:

- `problem-maker/js/smart-selection.js` 옆에 `ai-segmentation.js` 같은
  새 모듈을 추가하고, `SmartSelection`과 같은 인터페이스
  (`compute(seed, options) -> {alpha, pixelCount}` 또는 전체 이미지
  분할 결과를 알파 배열로 변환하는 형태)를 맞추면 `maker-app.js`의
  기존 확정/취소 로직(히스토리, 미리보기)을 그대로 재사용할 수 있습니다.
- 새 도구를 추가할 때는 버튼 이름을 실제로 AI 모델을 쓸 때만
  `AI 선택`이라고 표시하세요. 색상 유사도 기반 기능은 계속
  `스마트 선택`/`유사 색상 선택`으로 남겨두어야 합니다.
- 모델 추론이 무거우면 `problem-maker/js/utils/` 아래에 Web Worker를
  추가해서 UI가 멈추지 않게 하는 것을 권장합니다.
